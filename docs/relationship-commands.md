# Relationship commands in the retained preview

With AF enabled and a current Enterprise grid preview:

- To add a relationship, select its source node first, Ctrl-select its target, then right-click and choose **Add relationship** and an allowed type. The selection order determines direction. The command chooses free actual connection points, preferring facing sides and points near the centre. Adjust either point afterward using the circular endpoint handles described in [exact-connection-points.md](exact-connection-points.md).
- For a self-relationship, select one eligible node and choose an allowed **type to itself** from that menu. Its two ends use distinct free points. Either handle can change its point or reconnect to another node; reconnecting an ordinary relationship to its opposite node can also create a loop. Loop feedback follows an expanded node boundary with orthogonal segments.
- To remove a relationship, select its line and press **Delete**, or choose **Delete relationship** from the preview menu. Delete first cancels an active drag; press it again to delete the selected line. Modified Delete combinations do not invoke this command.
- Undo/redo uses the source editor's existing history. Each add or delete is one complete source replacement and one worker submission. Adding selects the new line; deleting clears it. Undo/redo restores the appropriate command selection even though a deleted/re-added declaration receives a new identity under the text policy.

Both commands use the same retained source transaction as typing. Failed local routing keeps the edited text for correction/undo, shows a stale-preview reason and retains the last accepted picture/export. No-op, stale, invalid and unavailable commands write nothing. Context menu callbacks capture source/document ownership, so an old menu cannot edit a newer document. AF-off controls are hidden; unsupported/stale previews disable their operations.

Eligible additions currently use ungrouped nodes/notes with free points in the supported inventory. Semantic tables and validation filter types; duplicate declarations are excluded. Self-relationships require two distinct points and an allowed semantic type; note self-connections are excluded. A plain connection requires a note. Plateau timeline topology requires an explicit new semantic layout and is excluded from the command menu. Grouped construction and diamond/circle/frame point inventories remain separate work. Visible group relationships can be removed without moving or refitting their groups. Labels are display/source content and do not determine capability.

Deletion also removes the line from indexed `linkStyle` directives and decrements later indices, retaining styling on surviving relationships. A directive targeting only the deleted line becomes an empty line. Source outside the required replacement is preserved, including LF/CRLF conventions. Geometry-affecting indexed style values are attached to the corresponding relationship in retained classification: moving its style index does not request initial layout, while changing a surviving relationship's font/stroke geometry still does. Native plain connections do not use those indexed style entries.

The current accepted SVG/PNG is the display/export authority. Pointer feedback and cancelled commands never replace those bytes. PNG copy uses the accepted PNG payload; selection outlines, handles and ghost feedback are excluded. Native source saves retain generated placement and endpoint hints. Reload reapplies these hints and computes the initial arrangement of otherwise automatic nodes; the source format does not promise to preserve every automatic cell or camera setting. Exact current appearance is available through SVG/PNG export. While the preview is stale, image copy/export keeps the last accepted arrangement and source save keeps the user's current text, including invalid edits.

With the existing `W_ArchiHintRoundTrip` switch enabled, Archi native, coArchi and Model Exchange paths retain relationship side/travel hints and signed point indices in `naiad.routingHint` custom properties. Cardinal placement offsets are retained alongside quadrant gaps and absolute positions in `naiad.placementHint`. These properties preserve source intent; external tools may ignore them. They do not store every automatic cell, route bend or viewport setting. Invalid routing properties are ignored without inventing a hint; disabling W omits these properties and generated suffixes. No arrangement round-trip beyond the persisted hints is promised for model exchange.
