# Retained layout session foundation

The internal `DiagramLayoutSession` in the shared layout library is the first engine slice of Phase 2. It can start with an empty canvas, so construction can proceed one explicitly placed node and one relationship at a time. A script adapter, toolbar drop or future context-menu command can submit the same operations. Capturing a completed, authoritative cell layout is an additional entry point.

## Operations and publication

`PrepareAddNode` accepts a node and an explicit whole-cell region. The caller supplies measured dimensions and shape geometry; this operation does not run initial placement. `PrepareAddRelationship` accepts an editor-owned relationship identity and endpoints already on the canvas. That identity survives `PrepareReconnect`, independently of endpoints and parser creation order. Parallel relationships use different identities. `PreparePorts` supplies endpoint-side/travel hints, including exact signed connection-grid steps. `PrepareMove` translates existing cell regions with fixed spans. `PrepareRemoveRelationship` removes one known identity, its route and guide while preserving surviving terminals, including vacant slots. Routes whose cycle policy changes enter its local dependency set; ordinary removal rebuilds zero routes. The placed canvas can retain zero relationships.

All operations fork the accepted routing inputs, grid ownership/gaps, node and group bounds, port geometry and routes. Each fork owns a fresh render context and caches. Semantic Enterprise constraint snapshots detach their contract inputs from the original parsed document. Shape geometry providers and custom region predicates must obey their existing immutable/pure contracts.

`PrepareRemoveNode` removes an ungrouped node and its incident relationships atomically. Source transactions require the parsed model to omit those relationships too. Removal retains vacancies, gaps, the model coordinate origin and surviving geometry, including when the last node is removed. Source-session tombstones remember removed regions so undo can restore unhinted nodes without rearrangement. First-placement origins survive deletion/undo as well. Semantic membership/row/alignment predicates ignore removed members while retaining constraints on surviving members; new nodes receive current semantic membership checks. Group containment/refitting and plateau triggering topology retain their separate construction/session requirements.

`PrepareResizeNode` accepts measured dimensions and an optional updated label. Its source equivalent plans new spans before resolving placement hints. Existing cells and grown internal gaps are reused; required growth reserves the smallest fitting span on each axis without moving unrelated owners. Relative-hint dependents follow the new complete region. Immutable request/span history restores earlier sizes on undo, including after deletion and coalesced edits. Nonfinite/negative/overflowing sizes, occupied reservations, proportional-shape failures and new frozen-frame clearance violations reject the candidate. Grouped cell growth still requires containment/refitting. Group-frame clearance is validated for all retained operations, independently of route legality.

Candidates route against supplied geometry. Changes include incident relationships and stored routes near the old/new obstacles. Endpoint allocation is checked against the old and new endpoint inventories; any peer whose terminal changes joins the dependency set. Expansion is monotonic and bounded by the local route limit. Frozen routes still participate in track repair and whole-model validation. A failed candidate is discarded, with a reason; there is no whole-diagram routing or initial-placement fallback. Existing findings are retained as baseline evidence; publication rejects additional route-rule findings. The reported route IDs distinguish the dependency set from routes submitted for rebuilding.

Retained allocation reserves explicit points first, then keeps legal existing neighboring points before distributing the remaining terminals. Free-side comparison respects the routing scope. A move to an unused point can therefore rebuild only that relationship; an occupied-point request includes any displaced neighbor. Empty active routing hints release the previous constraints. Immutable, candidate-owned allocation checkpoints remember terminals on edited endpoint owners, keyed by their geometry and incident routing requests. Returning to an earlier request restores displaced slots and includes those routes in the closure; failed candidates cannot modify the accepted checkpoints. Checkpoints belong to the current session and are not a source-file or camera persistence format. Their large-diagram memory cost remains part of the pending benchmark work.

`ObserveSourceRevision` runs when text changes, even if parsing will fail. A candidate carries its source revision and the layout revision it started from. `TryCommit` publishes only if both remain current and the candidate belongs to that exact session. Concurrent candidates cannot overwrite a committed successor, and a candidate cannot be committed twice. The accepted source revision remains unchanged on failure, so the next valid edit can compare against the last accepted model. `IsStale` exposes this difference.

`CopySnapshot` returns a detached routing model, geometry, document identity and accepted source/layout revisions together. `CopyLayout` returns only detached geometry. Reading either does not invoke routing or placement. Drawing extents can change without translating the model coordinate frame. Viewport transforms belong to the host and are not part of the engine session. New topology or hint inputs receive a fresh contract identity because existing topology helpers cache by contract identity.

## Current limits

- The API is internal. AF enables retained Enterprise grid source diffs, snapped node dragging and eligible endpoint gestures in LiveEditor. AG and AH retain their separate meanings and defaults; shared session operations do not depend on either UI switch.
- The shared [source update service](diagram-source-updates.md) now reconciles parser relationships, classifies edits and resolves typed node hints into one retained transaction with atomic source/geometry publication. The LiveEditor worker now uses this path, including existing text-editor undo/redo. GUI commands must write an undoable source change and submit that same path.
- Group insertion/refitting, grouped-node movement/sizing, grouped node removal and exact diamond/circle/frame inventories remain separate work. Typed node-hint replacement is implemented through the source service, rather than `PrepareMove`. Self-loop additions/reconnects use the existing fixed-geometry router and measured label clearance. Plateau triggering topology changes and invisible layout constraints require a new semantic/construction session. Unsupported operations must report their limitation or request an explicitly identified rebuild; they must not enter a fallback from a failed supported local edit.
- The routing-model copy intentionally omits source declarations, interactions and presentation styles. The host retains its full parsed document and must publish matching source metadata, presentation and geometry together. LiveEditor now renders candidate geometry and publishes matching source hit-test metadata, presentation, label placements and export images, with stale-preview reasons and camera preservation. Plain relationship label changes measure conflicts and request bounded route dependencies before publication. Grouped sizing remains pending; see [liveeditor-retained-preview.md](liveeditor-retained-preview.md).
- Transactions currently copy the complete retained model and run whole-model route validation. They avoid whole-diagram routing, but large-diagram latency and memory have not been benchmarked. Persistent dependency/spatial indexes, selective validation and copy-on-write state are subsequent optimizations; this slice makes no production speed claim.

## Verification

`DiagramLayoutSessionTests` exercises empty-canvas construction, isolated moves, added/moved obstacles, shared-terminal expansion, reconnect identity, endpoint-side changes, independent geometry preservation, failed-candidate rollback, stale source/layout results, cross-session rejection and detached snapshots. Existing scoped route and cell-repair tests remain relevant. Editor-level source/gesture equivalence, undo/redo, rapid document/flag switches and large-diagram benchmarks remain required before enabling interactions.

Validation on 28 October 2026: all 25 new session cases pass. The selected cell-repair, Enterprise-placement, rollback, layout-option and width-layout regressions total 92 cases: 87 pass and five fail. All five failures reproduce in a comparison build excluding the session files and reversing this change's supporting edits: `CrowdedBandGapGrowsAtomicallyBeforeRouting`, `WrapSelectionPublishesTheCheapestFullyRoutedCandidate`, both `RemoteCrossingRejectsAnOtherwiseStraightCellMove` directions, and `FrameOverlapRepairMovesWholeMemberRegions`. The normal build was rebuilt after that comparison. Logs are under `out/session-build.log`, `out/session-regressions.log` and `out/session-baseline.log`.
