# LiveEditor retained Enterprise preview

AF (`IncrementalDiagramRouting`) now connects Enterprise grid source edits to `DiagramSourceUpdateService` after analysis in the single LiveEditor worker. AF, AG and AH remain independent and default off. Ordinary AF-off, legacy-renderer and explicit open-layout previews use the existing rendering pipeline. Open mode shows an advisory explaining the retained-mode limit.

## Requests and publication

Each queued edit immediately advances the observed source revision and cancels older work, before debounce. An immutable worker request captures source, generation, editor text version, layout options, renderer and the document-session owner. The worker coalesces pending requests without starting overlapping layout passes. UI publication checks all current ownership/revision facts; engine publication additionally checks the accepted-layout revision.

The worker analyses once, then prepares metadata-only, redraw or local-routing updates. A successful candidate supplies detached source/geometry for drawing before acceptance. SVG generation, preview rasterisation, bitmap decoding and matching source hit-test/error metadata all complete before the engine transaction is published on the UI thread. A discarded/failed drawing does not accept its source revision. PNG/SVG preview copy and export use the displayed accepted image; SVG export cannot run initial layout when AF has no accepted drawing.

The retained state contains model/cell regions, routes, hints, identities and accepted source metadata. Every accepted edit generates a fresh SVG/PNG. The last successful image remains available for display/export while new text is invalid; it is not the geometry authority for routing.

PNG copy and file export preserve the accepted image payload without drawing selection/gesture overlays or entering layout. SVG export uses the accepted SVG; with AF enabled it refuses an export when no accepted drawing exists. Source save writes the editor's current text even when invalid, retaining explicit placement and exact endpoint hints for reload. Reload creates a fresh session, reapplies hints and arranges automatic nodes; it does not promise every retained cell, route bend or camera position. Archi/model-exchange hint properties follow the existing W switch. See [relationship-commands.md](relationship-commands.md) for the persistence contract.

## Failures and rebuilds

Invalid text, ambiguous identity edits and rejected supported local operations preserve typed text and the last accepted picture. The banner identifies the preview as stale and gives the reason, even when the ordinary keep-last-good-preview switch is off. The next valid revision compares with the last accepted model. A failed local transaction cannot become initial placement or whole-diagram routing.

Unsupported structural changes, labels/fonts, Enterprise title/configuration and other geometry-affecting presentation changes request a separately identified rebuild. A successful rebuild reports its reason in the preview advisory. Failed rebuild candidates leave the prior accepted state available. Switching documents, options or renderer permanently retires the incompatible session. The AF-only **View > Auto layout** command also retires it and starts fresh; ordinary Refresh keeps the accepted session.

`EnterpriseLayoutEngine.FromGeometry`, the supplied-layout routing context and the Enterprise drawing builder consume accepted geometry without entering the initial-layout entry point. Retained drawing bypasses the ordinary geometry-SVG cache. A fixed layout-to-SVG frame prevents recentering unrelated components; negative drawing extents expand the viewBox instead of translating model geometry.

## View and editing

Hit testing accounts for viewBox origin. Supported redraws preserve the model-to-screen scale and camera position across changed extents and preview raster downscaling. A fitted view becomes a fixed camera on the first supported edit so it does not automatically refit on every keystroke. **Fit preview** explicitly recomputes the view. These view changes do not run layout.

Existing text-editor undo/redo and GUI node drops enter the same source path. With AF enabled and a current accepted Enterprise grid preview, dragging an ungrouped regular element draws a dashed outline snapped to retained whole-cell geometry. The planner reads a detached grid once at gesture start and projects candidate regions, including expanded gaps and multi-cell spans; pointer movement performs no placement, routing or SVG/PNG generation. Zoom, viewBox origin, raster scaling and the pointer's grab offset are accounted for by the picture transform.

The available targets are the nearest placements expressible by above/below/left-of/right-of or NW/NE/SE/SW hints against another element in the same layer, with nonnegative whole-cell offsets up to 10000 per axis. Quadrant candidates snap rows and columns independently, so a destination can be offset in both axes without being restricted to a 45-degree ray. Relationships keep orthogonal segments and bends. Peers that depend on the moving element are excluded; when none remain, the gesture snaps directly to a logical cell and writes `at <row> <column>`. This supports lone nodes and placement anchors independently of their display labels. Group movement remains unsupported. Snap feedback is a proposed cell placement; collision and routing legality are checked by the shared worker on drop. See [diagonal-placement-hints.md](diagonal-placement-hints.md) and [anchor-free-placement.md](anchor-free-placement.md) for syntax and persistence.

Drag initiation retains the node hit before selection updates the floating details panel. If selection refits/repositions the picture, the grab point is rebased from its original screen position into the new picture coordinates. It is not hit-tested again after refitting. The dashed outline has a four-screen-pixel margin so it remains distinguishable from the solid selection border while snapping still selects the original cell; this margin does not affect the committed geometry.

The drag surface is the full viewport canvas. The picture retains native mouse capture so movement/release continue beyond the bitmap bounds. Feedback is painted in both the picture and the surrounding viewport using the same transformed rectangle, and both surfaces are invalidated on movement/cancellation to clear old feedback. The entire outline remains visible when it crosses the image edge or enters empty canvas space. Release inside the viewport can commit even when outside the image; release outside the viewport still cancels. This does not enlarge, regenerate or alter the accepted preview/export image during the gesture.

A valid release writes one declaration replacement through RichEdit's undo history. Its sole `TextChanged` notification submits the worker request. A click, an unchanged snapped position, Escape, capture/focus loss, a release outside the viewport, changed selection/view, source/document/options changes or a stale preview cannot commit the gesture. Escape cancels the drag while keeping its selected element; another Escape has the ordinary clear-selection behavior. Undo/redo reparse and route through the same worker. A rejected local drop keeps the new source hint for correction/undo and retains the accepted picture/export with a stale-preview reason, matching a rejected typed hint.

Selected relationships expose circular endpoint handles with AF and a current Enterprise grid preview. Drag a handle to an eligible actual point to reconnect or change its point; the opposite endpoint keeps its current point. Pointer motion uses a detached inventory and paints an orthogonal dashed path without routing or changing the committed line/image. Release writes one undoable declaration with signed `leave/enter side@step` hints. Invalid/no-op drops and cancellation write nothing. Stable identity restores selection after reconnect and undo/redo. Select source then target to add through the preview menu; select a line and press Delete to remove it. These commands share the worker/undo path, preserve indexed styles, and restore command selection after undo/redo. See [exact-connection-points.md](exact-connection-points.md) and [relationship-commands.md](relationship-commands.md). Ungrouped source node additions/removals and empty-source construction use retained transactions with exact construction undo/redo. Grouped moves/refitting, local label resizing, self-loop construction and exact diamond/circle/frame inventories remain pending. Unsupported source changes may rebuild; supported local failures stay rejected.

## Verification

LiveEditor opts into placement-origin capture for all retained source updates. Removing a node's first hint during the same session restores its pre-hint cell origin and resolves its hint dependents, including when a comment and the hint arrive in the same worker revision. This makes first-move undo restore both source and geometry. A fresh session loaded with an existing hint has no pre-hint origin to restore.
